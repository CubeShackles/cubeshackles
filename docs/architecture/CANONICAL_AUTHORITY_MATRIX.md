# CubeShackles Organization — Canonical Authority Matrix

**Status:** Discovery output. This matrix classifies each primitive using the code evidence collected in this census (see the other 3 `docs/architecture/*.md` files and the subagent evidence archive). It is checked, cell by cell, against the org's own DECLARED doctrine (`REPOSITORY_MAP.md` §15 "Canonical authority map"), and every disagreement between doctrine and evidence is surfaced explicitly, not silently reconciled in favor of either side, per the founder's explicit instruction. UNRESOLVED is used liberally where evidence is genuinely insufficient — it is not a failure state, it is the honest answer.

**Classification values:** CONFIRMED_CANONICAL / CANONICAL_CANDIDATE / DOMAIN_AUTHORITY / ADAPTER / DUPLICATED / CONFLICTING / SCAFFOLD / LEGACY / UNRESOLVED

## Summary of doctrine-vs-evidence contradictions (most important finding of this matrix)

1. **CIEL vocabulary**: doctrine names `cubeshackles-ciel`; evidence shows it has zero runtime relevance anywhere in the org. This is the sharpest contradiction found.
2. **Terrain "reality modeling"**: doctrine implies an operational registry; evidence shows a pure validation library with no persistence, live-wired in only 2 of ~11 repos that copy its pattern.
3. **JSON schemas and event contracts**: doctrine names `cubeshackles-contracts`; evidence shows real enforcement actually happens through a same-named-but-different package living inside Cubeshackles-core, with the doctrine's named repo consumed only as hand-copied path strings.
4. **Validator settlement truth**: doctrine names `cubeshackles-validator-node`; evidence shows the actual multi-validator quorum decision is made by node-api's orchestration code, not by validator-node itself.
5. **Network orchestration** and **OS kernel**: doctrine's designated repos self-disclose (in their own READMEs) that they are scaffolds without live wiring — doctrine overstates current maturity, not authority per se.
6. **Compliance gating** and **clearing decisions**: doctrine names real repos with real code, but neither is wired into the org's one working end-to-end institutional settlement path, which bypasses both via a hardcoded APPROVED decision.

None of these contradictions are resolved in this document — per the founder's explicit instruction, they are surfaced for a future decision, not silently corrected in favor of either the doctrine or the code.
